# P3 reference-edge review: freeze pending geometry, not its electrical approval

Reviewed input: `a2ebcb06f287b5862de05dc0357bb6b1dc8a61b8`, tree
`4535dfadc429d1c5bd8959c2a31f076ba74c3bc1`. Its complete saved source/history
was recovered, all 692 archive payload hashes checked, and Git objects checked.
This continuation changes the native reference checker, its tests and evidence
binding only. The auxiliary PCB, AFE PCB, BOM, schematic, firmware, carrier,
clearance rules, dependencies and release gates remain byte-identical.

## A real native counterexample

A ground-only keepout at `(79.45,19.49)` to `(79.65,19.69)` mm on In1 lies
beside the 0.60 mm TARGET_VIN5 trace, UUID
`90ba6800-0027-5595-a212-7b1f01cfa8dd`. It changes no signal copper. A new native
refill/DRC retained zero parity findings, zero other findings and zero airwires.
The original central-0.10mm reference-spine check also passed.

The reported full-width unsupported area nevertheless rose from
**0.0022883793065 mm2 to 0.0349032058185 mm2**, approximately **15.25 times**.
Both reports still contained **18 affected segment records**: asserting only
that count would miss the change as well. A same-size keepout displaced +2 mm
in X left the original reference results unchanged. This demonstrates a gap in
regression protection; it does not measure electrical interference or say that
this invented void exists on the actual board.

The earlier checker reported these findings but did not enforce that the
unresolved geometry stayed within the disclosed set. A passing central-spine
result could therefore accompany materially different, unreviewed edge geometry.

## Correction

`tests/fixtures/auxiliary_p3_pending_edges.json` captures the **20 native polygon
outlines belonging to the original 18 affected segments**, in integer KiCad
nanometre coordinates. They were extracted from an unchanged, freshly refilled
P3 copy. The source commit, PCB hash, explicit pending-review status and source
track UUIDs establish provenance. The fixture's byte identity is checked before
using it, and it is included in the shared schematic input-hash snapshot.
Changing its allowed locations now requires an explicit source change and review.

For every real routed segment, the native checker still computes the complete
trace-width projection and subtracts only the already-declared same-net contact
exclusions and the actual ground plane. It then subtracts the captured pending
polygons **on that same net and layer**. Additional area greater than the existing
`1e-6 mm2` numerical criterion is a failing reference check. Nothing enlarges the
original contact exclusions, central-spine tolerance, local P2 corridor, native
clearance rules, or any hardware permission.

The comparison is spatial, not a count, total-area allowance, or a dependence
on the current segment UUID. Known regions may shrink or vanish; they may not
grow or migrate elsewhere. This avoids rejecting harmless reversal or subdivision
of the existing affected trace. A remote keepout is likewise accepted. The
actual full-width findings are still emitted, and the output still explicitly
states that full-width coverage and physical performance are **not qualified**.

This is a regression boundary around unresolved geometry, **not approval of
those original gaps**. The original reference-spine limitations, via/antipad
exclusions, unknown stackup, current/edge-rate effects and long supply/control
paths still require electrical review. Source polygons are not manufacturing
tolerance or electromagnetic-field guarantees.

## Failure-first and native controls

The new edge-growth case failed against the old checker: DRC was clean but the
checker returned success. Separately, a software process double changed the
new fixture during a schematic run; the old input snapshot failed to detect
that change. Both failures were observed before implementing the corrections.
The fixture mutation is a software check, not a native electrical experiment.

Native positive controls retain clean connectivity and require the corrected
checker to accept the remote ground void, reversed affected trace and split
affected trace. Existing P3 terminal-cut, reference-void and benign-edit checks,
all P2 bypass/ground checks and P1 domain/mount guards remain unchanged in scope.
No PCB copper is repaired or regenerated by this review.
